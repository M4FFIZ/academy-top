# Недостающие элементы для ВКР

Тема: **Разработка модуля веб-сайта для АНО ПОО ММКЦТ «Академия ТОП»**

---

## Аннотация

В выпускной квалификационной работе рассматривается разработка модуля веб-сайта для АНО ПОО ММКЦТ «Академия ТОП». Разрабатываемый модуль предназначен для автоматизации взаимодействия между студентами, преподавателями и администрацией образовательной организации.

В работе выполнен предпроектный анализ предметной области, рассмотрены аналогичные программные продукты, определены функциональные и нефункциональные требования к веб-ресурсу. На этапе проектирования разработаны диаграммы IDEF0 и UML, спроектирована архитектура решения, структура информационной базы и пользовательские интерфейсы.

Практическая часть включает реализацию клиентской части на Next.js и React, серверной части на NestJS, базы данных PostgreSQL с использованием Prisma ORM, механизма авторизации JWT, чата и уведомлений в реальном времени на Socket.io. Проект размещён на облачной платформе Amvera и доступен пользователям по публичной HTTPS-ссылке.

Результатом работы является функционирующий веб-модуль личного кабинета, обеспечивающий просмотр расписания, оценок, посещаемости, работу электронного журнала, обмен сообщениями и выполнение административных функций.

## Перечень сокращений и обозначений

API — Application Programming Interface, программный интерфейс приложения.

Backend — серверная часть веб-приложения, отвечающая за обработку запросов, бизнес-логику и работу с базой данных.

Frontend — клиентская часть веб-приложения, отображаемая пользователю в браузере.

HTTP — HyperText Transfer Protocol, протокол передачи гипертекста.

HTTPS — защищённая версия протокола HTTP.

IDEF0 — методология функционального моделирования процессов.

JWT — JSON Web Token, токен, используемый для авторизации пользователя.

ORM — Object-Relational Mapping, технология сопоставления объектов программы и таблиц базы данных.

REST API — архитектурный подход к организации взаимодействия клиента и сервера.

SQL — Structured Query Language, язык структурированных запросов.

UML — Unified Modeling Language, унифицированный язык моделирования.

WebSocket — протокол двустороннего обмена данными между клиентом и сервером в реальном времени.

БД — база данных.

СУБД — система управления базами данных.

## Приложение А. Техническое задание

### А.1 Общие сведения

Наименование программного продукта: **модуль веб-сайта для АНО ПОО ММКЦТ «Академия ТОП»**.

Основание для разработки: выпускная квалификационная работа по специальности, связанной с разработкой веб-приложений и информационных систем.

Назначение разработки: создание веб-модуля личного кабинета образовательной организации, обеспечивающего цифровое взаимодействие студентов, преподавателей и администратора.

### А.2 Назначение и цели создания системы

Разрабатываемый модуль предназначен для автоматизации основных информационных процессов образовательной организации. Система должна обеспечить пользователям доступ к расписанию занятий, сведениям об успеваемости, посещаемости, сообщениям, уведомлениям и административным функциям.

Цель создания системы — повышение удобства получения учебной информации, централизация данных и улучшение коммуникации между участниками образовательного процесса.

### А.3 Категории пользователей

В системе предусматриваются следующие категории пользователей:

1. **Студент** — просматривает расписание, оценки, посещаемость, уведомления и сообщения.
2. **Преподаватель** — работает с электронным журналом, выставляет оценки, отмечает посещаемость и общается со студентами.
3. **Администратор** — управляет пользователями, учебными группами, дисциплинами, аудиториями, расписанием и аналитическими данными.

### А.4 Функциональные требования

Система должна обеспечивать:

1. авторизацию пользователей;
2. разграничение доступа по ролям;
3. отображение личного кабинета;
4. просмотр расписания занятий;
5. просмотр оценок и посещаемости;
6. работу преподавателя с электронным журналом;
7. управление пользователями, группами, дисциплинами, аудиториями и расписанием;
8. обмен сообщениями в чате;
9. отображение уведомлений;
10. работу с профилем пользователя;
11. хранение данных в базе PostgreSQL;
12. доступность веб-ресурса по публичной HTTPS-ссылке.

### А.5 Нефункциональные требования

Система должна соответствовать следующим требованиям:

1. интерфейс должен быть понятным и удобным;
2. страницы должны корректно отображаться на разных устройствах;
3. доступ к закрытым разделам должен предоставляться только авторизованным пользователям;
4. пароли должны храниться в хешированном виде;
5. система должна обеспечивать целостность данных;
6. основные страницы должны загружаться без значительных задержек;
7. архитектура должна позволять дальнейшее расширение функциональности.

### А.6 Требования к программному обеспечению

Для разработки и эксплуатации используются:

2. Next.js;

### А.7 Требования к безопасности

## Приложение Б. Руководство пользователя

### Б.1 Вход в систему

Для начала работы пользователь открывает веб-ресурс по адресу:

`https://academy-web-maffiz.amvera.io`

На странице авторизации необходимо ввести email и пароль. После успешного входа система определяет роль пользователя и открывает соответствующий личный кабинет.

Демонстрационные учётные записи:

| Роль | Email | Пароль |
|---|---|---|
| Студент | `student@top.ru` | `password123` |
| Преподаватель | `teacher@top.ru` | `password123` |
| Администратор | `admin@top.ru` | `password123` |

### Б.2 Работа студента

После входа студенту доступны разделы:

1. **Расписание** — просмотр занятий учебной группы.
2. **Оценки** — просмотр результатов обучения.
3. **Посещаемость** — просмотр сведений о посещении занятий.
4. **Чат** — обмен сообщениями с другими пользователями.
5. **Уведомления** — просмотр системных уведомлений.
6. **Профиль** — просмотр и изменение доступных данных пользователя.

### Б.3 Работа преподавателя

Преподаватель после входа получает доступ к разделам расписания, чата и электронного журнала.

В электронном журнале преподаватель может:

1. выбрать занятие;
2. просмотреть список студентов;
3. выставить оценку;
4. отметить посещаемость;
5. сохранить внесённые изменения.

После сохранения данные становятся доступны студентам в их личных кабинетах.

### Б.4 Работа администратора

Администратор имеет доступ к административной панели. В ней доступны функции:

1. управление пользователями;
2. управление учебными группами;
3. управление дисциплинами;
4. управление аудиториями;
5. формирование расписания;
6. просмотр аналитических данных.

Администратор отвечает за актуальность справочной информации и корректное наполнение системы.

### Б.5 Работа с чатом

Для отправки сообщения пользователь открывает раздел «Чат», выбирает диалог, вводит текст сообщения и нажимает кнопку отправки. Сообщение сохраняется в базе данных и отображается участникам чата в реальном времени.

## Приложение В. Руководство администратора

### В.1 Доступ к панели Amvera

Для администрирования развёрнутого проекта используется панель Amvera Cloud. В инфраструктуре созданы следующие сервисы:

1. `academy-db` — база данных PostgreSQL;
2. `academy-api` — серверная часть NestJS;
3. `academy-web` — клиентская часть Next.js.

### В.2 Переменные окружения backend-сервиса

Для сервиса `academy-api` используются переменные:

```text
DATABASE_URL
JWT_SECRET
JWT_EXPIRES_IN
PORT
CORS_ORIGIN
```

`DATABASE_URL` содержит строку подключения к PostgreSQL. `JWT_SECRET` используется для подписи токенов. `CORS_ORIGIN` должен содержать адрес frontend-сервиса.

### В.3 Переменные окружения frontend-сервиса

Для сервиса `academy-web` используются переменные:

```text
NEXT_PUBLIC_API_URL=https://academy-api-maffiz.amvera.io/v1
NEXT_PUBLIC_WS_URL=https://academy-api-maffiz.amvera.io
```

### В.4 Обновление проекта

Для обновления backend-сервиса необходимо отправить изменения в Git-репозиторий Amvera:

```powershell
git push amvera-api deploy-api:master
```

Для обновления frontend-сервиса:

```powershell
git push amvera-web deploy-web:master
```

После отправки изменений Amvera автоматически выполняет сборку и развёртывание проекта.

### В.5 Проверка работоспособности

Backend считается запущенным, если в логах отображается строка:

```text
API running on http://localhost:3001/v1
```

Frontend считается доступным, если открывается страница:

```text
https://academy-web-maffiz.amvera.io
```

## Приложение Г. Фрагменты программного кода

### Г.1 Подключение Prisma к PostgreSQL

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

Данный фрагмент показывает подключение Prisma ORM к базе данных PostgreSQL. Строка подключения хранится в переменной окружения `DATABASE_URL`.

### Г.2 Запуск backend-приложения

```typescript
const port = process.env.PORT ?? 3001;
await app.listen(port);
console.log(`API running on http://localhost:${port}/v1`);
```

Данный фрагмент отвечает за запуск серверного приложения NestJS на заданном порту.

### Г.3 Конфигурация CORS

```typescript
app.enableCors({
  origin: process.env.CORS_ORIGIN ?? 'http://localhost:3000',
  credentials: true,
});
```

Данный код разрешает клиентскому приложению отправлять запросы к backend API.

### Г.4 Конфигурация Amvera для backend

```yml
meta:
  environment: node
  toolchain:
    name: npm
    version: "22"

build:
  additionalCommands: npm run db:generate && npm run build -w @academy-top/api

run:
  command: npm run amvera:api:start
  containerPort: 3001
```

### Г.5 Конфигурация Amvera для frontend

```yml
meta:
  environment: node
  toolchain:
    name: npm
    version: "22"

build:
  additionalCommands: npm run build -w @academy-top/web

run:
  command: npm run amvera:web:start
  containerPort: 3000
```

## Чеклист оформления по ГОСТ и методическим требованиям

Проверь перед сдачей:

1. Титульный лист оформлен по шаблону колледжа.
2. Есть задание на ВКР, если его требует методичка.
3. Есть содержание с актуальными номерами страниц.
4. Есть введение.
5. Все разделы и подразделы пронумерованы.
6. Все рисунки имеют подписи вида: «Рисунок 2.1 — ...».
7. Все таблицы имеют подписи вида: «Таблица 3.1 — ...».
8. В тексте есть ссылки на каждый рисунок и таблицу.
9. Есть заключение.
10. Есть список использованных источников.
11. Есть приложения.
12. Каждое приложение начинается с новой страницы.
13. Приложения обозначены буквами: «Приложение А», «Приложение Б» и т. д.
14. В тексте есть ссылка на приложения, например: «Фрагменты программного кода представлены в приложении Г».
15. Шрифт основного текста — Times New Roman, 14 пт.
16. Межстрочный интервал — 1,5.
17. Абзацный отступ — 1,25 см.
18. Выравнивание основного текста — по ширине.
19. Поля: левое 30 мм, правое 10 мм, верхнее и нижнее 20 мм, если методичка не требует другое.
20. Нумерация страниц сквозная.
21. Номер страницы на титульном листе не отображается.
22. В работе нет упоминаний чужой темы, например «Чарышский район», если это не пример.
